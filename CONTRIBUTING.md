# Contributing

1. Pick an issue and read its linked files in the Docs repository.
2. Update the relevant contract before changing jobs, results, or artifacts.
3. Keep credentials, model data, and private content out of Git.
4. Add deterministic tests and benchmark model-dependent changes.
5. Run the repository and pipeline checks.
6. Review the full diff before pushing or opening a PR.

Use short branches and Conventional Commit subjects. Record model, prompt, embedding, sampling, and rubric versions when they affect output.

See the [review workflow](https://github.com/VirtuJudge/Docs/blob/main/Planning/Review-Workflow.md).
